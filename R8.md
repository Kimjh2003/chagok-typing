## 2026-11-01 release review

The current release retains R8 full mode, code minification and resource shrinking, without additional blanket keep rules. Rebuilt with `:app:assembleRelease -PlocalTestingSigning=true`: build and release lint vital succeeded, and `minifyReleaseWithR8` ran. The local test-signed APK is 160,854 bytes, with a 122,644-byte `classes.dex`; the earlier UX APK was 159,994 bytes and did not include the later motion/accessibility changes, so this is not an optimization benchmark. Inspection found no packaged `splash_branding` PNG or native libraries. The exact mapping is archived with this APK. No new R8 flags or performance claims were introduced without evidence. No connected device was available for release smoke or input/frame latency measurement.

`:app` release builds enable `isMinifyEnabled`, `isShrinkResources` and `proguard-android-optimize.txt`. R8 optimizes the complete app graph, including project libraries. Debug stays unminified for normal debugging. No extra R8 dependency or blanket feature-package keep rule is added; manifest entry points and platform callbacks use standard Android/AGP rules. Animators use typed View properties; storage uses explicit SQLite fields, not reflective model serialization.

Build locally installable release:
```
gradlew :app:assembleRelease -PlocalTestingSigning=true --offline
```
The explicit property signs release using the existing debug test key, allowing an in-place test update of previous APKs. It is a non-debuggable optimized release with a test signature, not a production-signed distribution. Without the property, release has no signing configuration and produces an unsigned artifact for separately configured production signing. No private signing keys are copied into source archives.

Keep `app/build/outputs/mapping/release/mapping.txt` with the exact APK for stack-trace retracing. `configuration.txt`, `seeds.txt`, `usage.txt` and resource reports are retained in the mapping folder. The mapping archive shipped alongside this build contains the exact release reports; rebuilding creates a different mapping and it must not be substituted for an older APK.

Validation: core/app/UI JVM regressions and all Android modules' release lint. ReleaseSmokeInstrumentation is a black-box device test using accessibility APIs and stable UI text, with no references to app classes renamed/removed by R8. It exercises launch, input, completion, successful persistence, history listing and expanded saved input. It is separate from the normal native IME test runner, which references unminified classes and is not an R8 release test.

Size comparison in this build: debug APK 2,897,068 bytes, release APK 81,746 bytes; uncompressed DEX 2,876,948 → 62,252 bytes. This is debug versus optimized release, so differences also include release packaging/debug information. It is not an isolated R8 benchmark or evidence of input-latency improvement.

Official guidance: https://developer.android.com/topic/performance/app-optimization/enable-app-optimization

The release smoke harness is the separate :smoke test-only APK (not part of the app dependency graph), bundling its own Kotlin runtime so R8 removal/renaming cannot break the test harness. Build with :smoke:assembleDebug; install smoke/build/outputs/apk/debug/smoke-debug.apk; run adb shell am instrument -w dev.typing.smoke/dev.typing.smoke.ReleaseSmokeInstrumentation. Normal :app Android tests remain on the debug app.

Verified on Android 36.1 emulator: optimized release passed launch → text input → completion → saved status → history → expanded saved input. The first screen-test attempt was blocked by an emulator System UI ANR dialog; retry after dismissing it passed. JVM tests (14) and production modules' release lint passed. ARM64 physical-device behavior/performance remains unmeasured.
